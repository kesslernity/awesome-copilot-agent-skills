# Action-items document template

Produce the action-items document with exactly this structure. Replace angle-bracket placeholders. Keep section order. Leave a section's body as "None found." rather than deleting the section. Return the whole document in the chat; the document name is actions-<YYYY-MM-DD>-<meeting-slug>. Storing it is the user's action.

```markdown
# DRAFT: Action items, <Meeting name>, <YYYY-MM-DD>

> Generated by the transcript-to-actions skill on <run date YYYY-MM-DD>. DRAFT until reviewed by a human.

Source transcript: <attached file name, meeting name, or "pasted text">
Attendees (as listed): <names, or "Not listed">

## Decisions

1. <Decision in one sentence.> Source: "<verbatim fragment>"

## Action items

| # | Owner | Action | Due | Source quote | Task status |
|---|---|---|---|---|---|
| 1 | <Name or Unassigned> | <Verb-led action> | <YYYY-MM-DD or No date given> | "<fragment>" | <to enter / not requested> |

## Open questions

1. <Question.> Raised by <name or "unclear">. Source: "<verbatim fragment>"

## Handover log

- Document: returned in the chat as <document name>; storing it is the user's action
- Task destination chosen: <personal task list "Meeting actions" / plan or board "<name>" / document only>
- Tasks proposed for the user to enter: <n> of <total>, or "none, document only chosen"
- Email drafts prepared: <n> (owners: <names>); drafts without a resolvable recipient: <names or "none">
- Left for the user: store the document, enter the tasks, attach or link the stored document in each email, review and send the emails
```

Rules:

- The title line and the blockquote must both carry the word DRAFT.
- Task status is "to enter" for every item when a task destination was chosen, or "not requested" when the user chose document only. The agent creates no tasks, so no other value exists.
- Do not add sections beyond the header block and these four.
- Any field that cannot be established from the transcript or the user's input reads UNKNOWN.
