# Owner covering note template

One note per resolved system owner. The agent drafts the text; the user sends it. No note is drafted for the "Owner to assign" section, for a group, a shared mailbox or an outside address.

## Shape

Recipient: <owner as resolved from the mapping>

Subject: Access review for <system or systems>: your decisions requested

Body:

1. One sentence naming what the user will attach or paste with this note: the owner's section of the access review pack for <systems>, dated <review date>, with <line count> lines across <account count> accounts.
2. One sentence on what the flags are: questions to confirm, raised from the export by rule, not findings; an unflagged line still needs a decision.
3. Flag counts for this owner, one line each, only the flags present: for example "Leaver: 2, Dormant: 7, Privileged: 3, No flag: 41."
4. How to complete: enter one value per line in the Owner decision column (Keep, Remove, Reduce, Transfer, Cannot decide) and use Comment for the target level, the transferee or the right decider.
5. What happens next: lines marked Remove, Reduce or Transfer are raised through the usual request or change path after the owner returns the section; nothing changes as a result of the review itself.
6. Return by: <date>. Include this line only if the user stated a return date. Otherwise omit it entirely; never propose one.
7. Sign-off as the user, not as the agent.

## Rules

- No deadline, escalation or consequence the user did not state.
- No additional recipients, no copy lines, no forwarding suggestion.
- Counts in the note equal the counts in the owner's section of the pack.
- The note never states that access has been, or will be, removed by anyone; it asks for decisions.
- The notes are section 8 of the pack document, one per resolved owner, with no separate file or title. If the user asks for the notes alone, return them as `DRAFT-access-review-notes-<scope>-<YYYY-MM-DD>-v1`. The agent sends nothing.
