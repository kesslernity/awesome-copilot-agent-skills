# Service catalogue entry: default field set

Used when the organisation has no catalogue template of its own. When a template exists, its field names and order win; map these fields onto it and record the mapping in the report. Every field appears in the entry. A field with no supporting input reads UNKNOWN and gets a numbered question.

## Fields in order

| Field | What it holds | Fill only from | UNKNOWN wording |
|---|---|---|---|
| Service name | The name the service team uses, singular, no internal codenames unless the team wants them shown | Inputs | UNKNOWN: name to be confirmed by service owner |
| Short description | One sentence, under 160 characters, what the service gives the user | Description facts in inputs | UNKNOWN |
| Description | Two to four sentences: what the service does, for whom, the outcome it supports | Inputs | UNKNOWN |
| Audience and eligibility | Who may use or request it (roles, units, locations) | Inputs | UNKNOWN: eligibility to be confirmed |
| In scope | Bulleted list of what the service includes | Inputs that place the item in scope | Not stated (see questions) |
| Out of scope | Bulleted list of what it excludes and, where stated, where that is covered instead | Inputs that place the item out of scope | Not stated (see questions) |
| Service owner | Role or team accountable for the service; a person only if named in inputs | Inputs | UNKNOWN: owner to be named |
| Technical or delivery owner | Role or team running the service day to day | Inputs | UNKNOWN |
| Support group and escalation | First-line group, escalation route, as named | Inputs | UNKNOWN |
| Support hours | Hours and time zone, as stated | Inputs, verbatim | UNKNOWN: to be provided by the service owner |
| Service levels | Availability, response and resolution by priority, fulfilment lead time, recovery objectives, maintenance windows; each verbatim with unit and condition; block labelled "as provided by <source>"; aspirations marked | Inputs, verbatim | UNKNOWN: to be provided by the service owner |
| Request path | Who may request; channel as named; approvals and by whom; information the requester supplies; fulfilment steps and lead time as stated | Inputs | UNKNOWN |
| Getting help | How to report an incident or ask a question about the service, as named | Inputs | UNKNOWN |
| Dependencies | Underpinning services, platforms, suppliers, as named | Inputs | UNKNOWN |
| Related entries | Other catalogue entries the team names as related | Inputs | None stated |
| Charging | Cost model, price, cost centre or recharge rule, as stated; never estimated | Inputs, verbatim | UNKNOWN: charging to be confirmed |
| Data and compliance notes | Data classification, retention, regulatory notes, as stated | Inputs | UNKNOWN |
| Lifecycle status | Planned, pilot, live, retiring, retired, as stated; never inferred from tone | Inputs | UNKNOWN |

| Keywords | Search terms the team or inputs use for the service | Inputs | None stated |

## Writing rules for the entry

- Plain sentences, present tense, second person or neutral ("You can request", "The service provides"). No marketing adjectives, no superlatives.
- No commitment words absent from the inputs: always, guaranteed, 24/7, immediate, unlimited, seamless, best in class.
- Figures, hours and names appear exactly as the inputs give them, with their unit and condition. Nothing is rounded, converted or tightened.
- Where the audience is technical, the description may name components and interfaces the inputs name; where the audience is business, it names outcomes and leaves components to Dependencies.
- A Conflict between inputs is shown in the field as "Conflict: <value A> (<source A>); <value B> (<source B>)" and carries a question. The agent never chooses.
- The entry stays DRAFT until the service owner approves it. Publishing is the catalogue administrator's action after the service owner approves the text; the agent publishes nothing.
